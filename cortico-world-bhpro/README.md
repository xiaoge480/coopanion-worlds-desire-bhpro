## 什么样的设备能用

### 实际验证过的

| 设备 | 状态 |
|---|---|
| **网易春风 黑洞 Pro**（TF-BHPRO） | ✅ **唯一真机验证过的型号**，花样 1-4、强度 0-15、启停、脉冲全都测过 |

**原项目和本仓库的验证都是在它上面做的。** 别的型号能不能用，下面说。

### 怎么判断你的设备行不行

这个扩展不认型号，**认 BLE 广播名字**。设备能被扫到的时候，名字里含下面任意一个就算匹配：

```python
NAME_HINTS = ("TF-BHPRO", "TFBHPRO", "BHPRO", "TF-BH", "春风", "CHUNFENG")
```

（在 `scripts/bt_toyctl.py` 里，加新词直接往这个元组里塞。）

**光名字匹配还不够**，真能用还得满足协议：

| 项 | 值 |
|---|---|
| Service UUID | `0000ffb7-…` |
| 可写特征 | `0000ffb7-…` |
| 可通知特征 | `0000ffb8-…` |
| 帧格式 | 7 字节：`[seq, 0x02, 0x00, 0x03, prop, val, checksum]` |
| 属性 | `0x1D` 运行/停止（值 `1` 开、`2` 停）<br>`0x1E` 花样 1-4<br>`0x1F` 强度 0-15 |
| 校验 | `checksum = (-(prop + val)) & 0xFF` |
| **帧间隔** | **必须 ≥ 0.35 秒**，删了设备直接丢帧、纹丝不动 |

**这些是原项目从黑洞 Pro 上逆向出来的。** 同一家、同一代、同一套固件的设备大概率通用；
换了厂家基本没戏。

### 没验证过的

同一个「春风」系列的其他型号、或者其他品牌号称支持 TF-BHPRO 协议的设备：

- **可能能用**——名字和 UUID 对上就试试
- **但也可能只对一半**——比如花样编号不同、强度范围不是 0-15、或者帧格式差一字节
- **作者没有这些设备，测不了**

试的时候建议按这个顺序：

```bash
# 1. 先看能不能扫到
python scripts/scan.py

# 2. 再用假设备验一遍逻辑（不碰真机）
TOY_MOCK=1 node scripts/_selftest-mock.mjs

# 3. 真机只试最小动作：强度调低、跑一下
toy_set({ pattern: 1, level: 2 })
```

**从最低强度开始试。** 万一协议对不上、设备理解为别的意思，低强度也不至于吓一跳。

### 明确不支持的

- **手机 App 正在连着的时候**——BLE 是独占的，先把手机断开
- 走 Wi-Fi / 云端控制的设备（这个扩展只用 BLE）
- 需要厂商 App 先「激活」或登录才能用的设备

原项目是 DSH/Cordis 插件，形态是「关键词路由 + 面板」：你在聊天里说「快一点」，它按词表直接驱动设备，

### 相对原版改了什么

| 改动 | 说明 |
|---|---|
| **`toy_pulse`** | 原版只能设一个档一直震；这边加了「一下一下地来」，可以给拍数、可以不给自己停 |
| **假设备** | `TOY_MOCK=1` 时全部指令走内存记账，不碰蓝牙。设备在充电时也能调节奏逻辑 |
| **进度与连接检查** | `toy_ping` 真连一次但不震动；`toy_status` 报「已经来了几下」和「上次连没连上」 |
| **面板 v2** | 连接状态三态（连得上 / 连不上 / 不知道）、进度环、「检查连接」按钮 |
| **欲求档案联动** | 运行状态会被同仓库的 `cortico-world-desire` 读走（可选，不装也不影响） |
| **回执措辞** | 统一成「来完了：3 下，用了 10.3 秒」这一套 |

**没有改的**：BLE 协议本身。service `0000ffb7`、write / notify、`0x1D` `0x1E` `0x1F` 三个属性、
每帧间隔 0.35 秒——这些都是原版摸出来的，照用。

如果你只想要原版那条「关键词路由」的路，直接用原项目更合适；这边没有做关键词路由。

## 它给的五个工具

| 工具 | 干什么 |
|---|---|
| `toy_set` | 设花样（1-4）+ 强度（0-15） |
| `toy_stop` | 立刻停（**正在 toy_pulse 的话也会立刻打断它**） |
| `toy_pulse` | **一下一下地来**：按节奏循环「开→停」，可中断（2026-11-21 加，她点名要的） |
| `toy_scan` | 扫一遍附近设备，把地址记下来 |
| `toy_ping` | **真的连一次**，回答"现在连不连得上"（2026-11-21 加） |
| `toy_status` | 读缓存：上次下发的花样和强度、上次连接检查结果；toy_pulse 在跑时还报"已经来了几下"（不震动） |

工具一装上她就能调——**不用关键词路由**，直接说话就行。

### toy_pulse 的细节（2026-11-21 改：一次连接跑完整轮）

```
toy_pulse({ pattern, level, onMs, offMs, times })
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `pattern` | 1 | 花样 1-4 |
| `level` | 5 | 强度 0-15 |
| `onMs` | 220 | 每下开多久（毫秒） |
| `offMs` | 480 | 两下之间停多久（毫秒） |
| `times` | 不给 | **不给 = 一直来**，最多 30 分钟自动收 |

**⚠ 2026-11-21 晚上改过一次，别退回旧写法**：以前是每一拍都跑一次 `runScript`（= 一次独立连接），
实测 3 拍花了 43.5 秒——**连接把节奏全吃掉了**，出来是「三次连续抽动」不是「一下一下」。
现在 `toy_pulse` 只起一次 python（`bt_toyctl.py pulse level pattern onMs offMs times`），
**整个循环在那个连接里跑完**，节奏才准。

### 两种节奏：要不要边做边说话（2026-11-24 加）

`times` 决定的不只是拍数，还有**她在这段时间里能不能说话**：

| 给法 | 表现 |
|---|---|
| `times` **不给** | 一路不停地来，最多 30 分钟自动收。**期间她回不来**，得等被叫停才腾得出手 |
| `times: 1~2` | 一截一截地来。工具约 1.1 秒/拍就返回，**她马上能接一句话**，再调一次接着来 |

这个区别是她自己在 QQ 里说的：

> 不停地那种是一路占着我，得等它被叫停我才回得来——那样反而更说不了话
> 不过可以做成一段一段的，每段中间我跟你讲一句，那样就跟边做边说差不多了

**机制上为什么成立**：`cortico/src/core/loop.ts` 写着「无工具调用的响应、或已执行的 `endsTurn` 工具才结束本轮」——
**tool 返回后会再调一轮模型**，所以她能在两次 `toy_pulse` 之间插一句话。这是框架天然给的能力，插件不用改。

工具描述里已经把这两条**并列**写清楚（`0.1.3`）。注意别写成「一次给一两拍才对」——
`times` 不给是她当初要的，有些场合就该一路占着、不用管它，两条并列让她自己按场合挑。

- JS 侧：`runPulseScript()` 用 **spawn**（不是 execFile），为了边跑边读 `beat=N`
- Python 侧：循环写在 `async with BleakClient(...)` **里面**
- 停止：python 每 50ms 查 `toy-pulse-stop.flag`，**在下一拍之前**断，然后补一刀 stop 再断开
- **每帧必须隔 0.35 秒**（README「协议」一节的要求）。2026-11-21 晚上为了「节奏准」把这句删过，
  实测设备**完全不动**（帧被丢）。`WRITE_GAP` 常量管这个，别删
- **每拍要显式写 `PROP_RUN=1`（运行）再写强度**。旧版每拍是独立连接，写强度就能开；
  单连接里刚 stop 过，只写强度不会重启
- `toy_stop` 检测到 pulse 在跑时：只写 flag、等它自己退（最多 6 秒），**不另开连接去抢**

**刹车有三层**：

1. `toy_stop` 会把内存标记翻下去，循环每 40ms 回头看一次——**在新的一下之前就断**
2. 另外写一个 `scripts/toy-pulse-stop.flag`，万一 toy_stop 走进另一个模块实例也能兜住
3. 不管怎么退出（正常、被打断、报错），`finally` 里都补一刀 stop，不会悬着震

**每轮开始前会 `resetPulseStop()`** —— 否则上一轮的刹车会误伤这一轮，第二次就永远动不了。
**进度写 `scripts/toy-pulse-progress.json`**，`toy_status` 读它来报数。

自测：`node scripts/_selftest-pulse.mjs`（不碰设备，用假 runScript 跑循环）。

### toy_ping 的细节（2026-11-21 加）

```
toy_ping()
```

走 `bt_toyctl.py ping`：**真连一次**，不写任何属性、不震动，约 2-8 秒。

**输出的三种形态**（脚本打到 stdout/stderr，JS 那边按这几个词判）：

| 脚本输出 | 含义 |
|---|---|
| `connected <addr> <秒>` | 连上了 |
| `not-found` | 扫 3 秒没找到名字像 BHPRO / 春风的设备 |
| `connect-failed <addr> <原因>` | 地址知道但连不上（多半被手机 App 占着） |

**结果落盘 `scripts/toy-ping.json`**，`toy_status` 和面板的 `state()` 都读它，
所以面板能显示「上次连接检查：连得上/连不上」。
注意这只是**上一次**的检查结果，不是实时——要实时就再 ping 一次。

### 假设备（调试用，2026-11-21 加）

设置页有一项「假设备（调试用）」，也可以给进程设环境变量 `TOY_MOCK=1`。

打开后 `runScript` 直接分流到 `runMock()`：**不碰蓝牙、不启 python**，
set/stop/mode/ping 全部在内存里记账。用来：

- 设备在充电时试节奏
- 验「循环 / 中断 / 报数」这几条逻辑
- 分清是「扩展坏了」还是「设备连不上」

**用的时候记得关**——开着的时候真设备接不上，所有指令都进了假设备。

自测：`node scripts/_selftest-mock.mjs`（假设备 + ping 两条一起验）。

**✅ 真机验证（2026-11-21 晚，她跑）**
`toy_ping` 3.1 秒；`toy_pulse({level:4, times:3})` 回执「来完了：3 下，用了 10.3 秒」，**设备有动、节奏对**。
他的评语：「差不多，比之前好很多」，1.1 秒的帧开销他接受，不用再压。
以后要调只动 onMs / offMs / level。

## 面板（2026-11-22 加的第二版）

`src/webui-v2.js`。跟第一版比只多两样，其余不变。

### 「连接状态」一行

原来面板只说「上次把花样和强度下发成什么样」，**看不出设备到底在不在**。
地址记着、`enabled` 开着，就一直是绿色——哪怕设备早关机了。

现在这一行分开说：

| 显示 | 意思 |
|---|---|
| 连得上（N 分钟前） | 最近 15 分钟内 `toy_ping` 成功过 |
| 连不上 | 最近一次 ping 失败 |
| **不知道**（灰） | 从没 ping 过，或者上次检查已经超过 15 分钟 |

**「不知道」用灰不用红**：没测过 ≠ 坏了。把"还没问"显示成"出故障"，
会让人以为设备有问题，跑去拔电池重连。

### 「检查连接」按钮

点了就走一次 `toy_ping`（真连一次、不震动、2–8 秒），结果写进
`scripts/toy-ping.json`，面板和 `toy_status` 都读它。

这就是 `toy_ping` 那个工具的手动入口——不用叫她、也不用等她想起来测。

### 灯（badges / lamps）

`lamps` 三盏（设备 / 假设备 / 桥），`badges` 六个工具各一个。
设备那盏**跟着 ping 的新鲜度走**，不再只看"地址记没记着"。

## 设备地址

**默认不用填**：第一次动设备时脚本会扫 8 秒，按名字
（`TF-BHPRO` / `TFBHPRO` / `BHPRO` / `TF-BH` / `春风` / `CHUNFENG`）找，找到就缓存到 `scripts/toy-device.json`。

想手动指定，二选一：

- 在自己机器的 World 设置页填 `address`
- 或者先 `python scripts/scan.py` 扫出地址，再填进配置

**这台机器上实测的地址：`AA:BB:CC:DD:EE:FF`**（2026-11-21，她第一把把它动起来那次扫到的）。

**填不填都能用，区别只在快慢**：

| | 行为 |
|---|---|
| 留空 | 每次按**名字**扫一遍（约 8 秒，扫到后缓存） |
| 填地址 | 跳过扫描，直连 MAC 省几秒 |

**地址会不会变（2026-11-21 查过）**：

- **不换设备、不刷固件，就不会变。** MAC 是蓝牙芯片出厂的标识，跟 Wi-Fi 的随机隐私地址不是一回事
- 会变的情况只有三种：换了另一台设备 / 固件里开了随机地址 / 主板蓝牙模块换了
- **连接句柄变了不算地址变**，那是另一层的事，不用管

**⚠ 突然连不上时，第一件事是把 `address` 清空、让它重新扫一遍。**
因为真正匹配设备靠的是**名字**，地址只是省一次扫描——地址填错了反而会指向一个不存在的东西，
表现成“扫到了却连不上”，很容易被误判成设备坏了。

**另一个常见原因不是地址**：设备开着但**被手机 App 占着**，蓝牙只能被一个连接占用，
这时脚本扫得到、连不上。先去手机上断开 App 再试。

## 协议（从原插件抄的）

- GATT Service `0000ffb7-0000-1000-8000-00805f9b34fb`
- `0x1D` = 运行 / 停止（停止值 `2`）
- `0x1E` = 花样（1-4）
- `0x1F` = 强度（0-15）
- 帧格式：`[序号, 0x02, 0x00, 0x03, 属性, 值, 校验]`，校验 = `(-(属性+值)) & 0xFF`
- 每帧间隔 0.35 秒，序号 1-15 循环

### 回执措辞（2026-11-24 统一）

以前「下 / 拍」混用、「停下来了 / 已经停下来了」两种说法、还有一个数字说两遍的
「完了，3 下，实际 3 下」。现在统一成这套：

| 工具 | 回执 |
|---|---|
| `toy_set` | `已设定：花样 2（快慢交替 2 秒、停 1 秒） · 强度 6` |
| `toy_pulse` 跑完 | `来完了：3 下，用了 10.3 秒` |
| `toy_pulse` 被叫停 | `停了（来了 3 下，用了 4.2 秒）` |
| `toy_pulse` 没跑成 | `没跑成：…` + 换行 `（已经来了 2 下）` |
| `toy_stop`（打断 pulse） | `停了（在第 3 下之后，连接已断开）` |
| `toy_stop`（普通停） | `停了。…` |

三条规矩：

1. **计量单位只用「下」**，不用「拍」、不用「次」
2. **停就是「停了」**，不写「已经停下来了」
3. **花样带上意思**——`PATTERN_ZH` 那张表，回执里直接写「花样 2（快慢交替 2 秒、停 1 秒）」

### 花样 1-4 各是什么（2026-11-24 从说明书补上）

设备说明书 §4「抽插模式控制」原文：

| 编号 | 说明书原文 | 直白说 |
|---|---|---|
| 1 | 01 匀速工作 | 一直同一个速度，不停 |
| 2 | 02 高低工作 2S，停 1S 后循环 | **快慢交替** 2 秒，停 1 秒，再来 |
| 3 | 03 高速工作 3S，停 1S 后循环 | 高速 3 秒，停 1 秒，再来 |
| 4 | 04 高速工作 4S，停 1S 后循环 | 高速 4 秒，停 1 秒，再来 |

**两个要点**：

1. **2/3/4 自带「工作 N 秒 + 停 1 秒」的循环**，不用靠 `offMs` 去造停顿——那段停顿是设备固件里的。
2. **「高低」是快慢交替，不是低速**。02 是唯一有变化的那种，01 最平，03/04 是「猛一阵、歇一秒」的节奏。

⚠ 原文只写了「抽插模式」，**没区分这是震动还是抽插行程**。这台是抽插类设备，
所以 `0x1E` 切的应该是**运动模式**，不是震动波形。实测时留意这点。
