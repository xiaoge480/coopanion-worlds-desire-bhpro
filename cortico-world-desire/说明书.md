## 一句话

**她这一阵子过成什么样，会留在身上，而且会自己往下走。**

不是开关，是一条一直在动的量。关机那几小时也算——隔一天打开，该涨满就涨满。

---

## 四个数是什么

| 数 | 是什么 | 怎么变 |
|---|---|---|
| **欲求** | 想要的程度 0–100 | 一直在涨；越久没被满足涨得越快；被满足会掉 |
| **满足** | 刚被喂过的饱足 0–100 | 事后升高，每小时衰减；**高的时候压住欲求** |
| **留存** | 身体里还留着的量 0–100 | 只有「灌满」会加，每小时自然吸收 |
| **敏感** | 最近 72 小时的密度 | 只按最近的事算，不靠时间涨；它只影响**涨多快**，不是面板上的数 |

**核心图就是这四个数的可视化**：核的颜色和呼吸快慢是欲求，水位是留存，两侧的环是满足和设备。

## 数据从哪来（这是最容易出问题的地方）

三个来源：

| 来源 | 位置 | 取什么 |
|---|---|---|
| **日记** | `notes/年-月-日.md` | 只要**生活小节** |
| **QQ 私聊** | `data/session-main.jsonl` | 只要真过了 QQ 的话 |
| **交接笔记** | `handoffs/*.md` | 只挑里面嵌着的私聊 |

### 怎么剔掉杂音

日记里她的小节标题自己就在区分：

```
## 17:23 小屋（第8天）        ← 生活，要
## 12:47 交接前（此刻正做到一半）  ← 工作记录，整节跳过
## 18:06 外设（TF-BHPRO）接上了   ← 调设备，整节跳过
```

标题含「交接 / 待办 / 外设 / 调试 / 配置 / 工具 / 清单 / 日志」→ **整节不看**。

## 我踩过的坑（六个，同一个病）

**病根只有一个：我写给你看的解释，被它当成了她经历过的事。**

因为我们一边调它一边说话，我说的话里全是「灌满」「液面」「只认私聊」这些词。

七次翻车依次是：

| # | 漏在哪 | 修法 |
|---|---|---|
| 1 | 工具输出（我读笔记的内容）被当文本 | 只收带 `[私聊]` 标记的 |
| 2 | **我的回复**（assistant）被当她的经历 | 排除 `role=assistant` |
| 3 | 讨论功能的句子被认成事件 | 加「工程词 ≥2 就跳」 |
| 4 | 词表写法 `（灌满 / 揉 / 亲）` 也像真事 | 括号里带斜杠 → 跳 |
| 5 | **我引用的聊天片段**（`[私聊 在行中间`） | 判据改成「行首」 |
| 6 | **缩进两格的示例**（`  [私聊 20:41]`） | `^\s*` 里的 `\s*` 删掉，**必须顶格** |

**现在这条链是这样**：真记录顶格、带 `#id`；我的示例必然缩进或带符号。形式判据比内容判据可靠得多。

### 时间线也错过一次

`12:28 灌满` 那条，事其实发生在 **00:35**（note 里写着 `[私聊 00:35]`），
但被记在「我扫到它的时刻」，于是排到了「00:00 一次」上面。

现在：**记录时刻 ≠ 发生时刻**，从 note 里取 `[私聊 HH:MM]`，日期从文件名取。

## 你看到「不清零」的时候，怎么判断是真还是错

面板上「欲求 0、满足 99、距上次满足十几分钟」——这个组合**基本就是误记**。

真的一次灌满，欲求确实会掉到很低，但**满足不会一直贴着 99**（它会每小时掉 10）。
两个一起出现，说明有一条假的 fill。

> **2026-11-25 补**：以前「被撩」（`heatRelief` 是 -8，只会让她更想要）也会把
> 「上次满足」刷成那一刻，所以这个时间可能比实际新。现在只有真降欲求的事件才更新它，
> 上面这个判据比之前可靠了。同一天还修了「119.9 分钟显示成 1 小时」和
> 「留存见底了还显示 4/时」两个小问题。

### 查/救的两个脚本

```bash
# 看有哪些是误记的（不写文件）
node test/undo-event.mjs dryRun

# 撤掉误记那条的影响
node test/undo-event.mjs
```

它做的事：删掉假事件，然后把那次误扣的欲求加回来、误加的满足减回去，
再把「上次满足」退回到真正的那一次。**每次都会先备份 state.json。**

```bash
# 只想按公式重算一遍（不依赖当前值）
node test/recover-heat.mjs dryRun
```

## 命令和配置

### 四个工具（给她用）

| 工具 | 干什么 |
|---|---|
| `desire_status` | 看现在什么状态 |
| `desire_touch` | 记一次亲密的事（七档里挑一个） |
| `desire_remember` | 从最近写的笔记里回想发生过什么 |
| `desire_tune` | 直接拨数字，或者把「上次被满足」改成现在 |

### 关键配置（`config.json` 的 `worlds.desire`）

| 项 | 默认 | 说明 |
|---|---|---|
| `heatRatePerHour` | 6 | 每小时涨多少（还会乘刹车、加速、敏感） |
| `satietyDecayPerHour` | 10 | 满足每小时掉多少 |
| `absorbPerHour` | 4 | 留存每小时吸收多少 |
| `autoScanMinutes` | 10 | 多久扫一次聊天记录 |
| `chatLog` | — | 聊天记录路径 |
| `workspace` | — | 工作区（日记和交接笔记在这儿） |
| `selfReliefAt` | 75 | 欲求到这个值她会自己解决（如果开着） |

## 装/卸

```bash
cd <Coopanion 安装目录>/data/extensions
pnpm add link:~/.dsh/cortico-world-desire \
  --store-dir "<Coopanion 安装目录>/data/pnpm/store"
```

**改了 `src/` 或 `web/` 之后要 bump 版本号再重启**——
面板资源的 URL 里带着 `package.json` 的 version，版本不变浏览器就一直吃缓存。
今天为这个白改了三轮。

```bash
node test/bump-version.mjs "改了什么"
```

面板右上角有个 `v0.x.x`，**你看到它变了才说明新代码真到了**。
